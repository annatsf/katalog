# ESCORE — Пошук обладнання у постачальників

Веб-каталог, який дозволяє проєктанту чи менеджеру знайти обладнання за характеристиками
і одразу побачити, **у кого воно є в наявності**, **ціну** та **посилання на datasheet**.

**Живий сайт:** https://annatsf.github.io/katalog/

> «Наявність» і «ціна» беруться **зі слів постачальника** — перед замовленням підтверджуйте.

## Автономність

Це **самостійна робоча копія** каталогу. Вона не читає нічого з іншого репозиторію:
власний `build.mjs`, власний `catalog.json`, власний розклад GitHub Actions, власний GitHub Pages.
Єдине спільне з оригіналом — **зовнішні джерела** (сайти постачальників і Google-таблиці),
і всі вони зібрані в одному місці: блок **`SRC`** на початку `build.mjs`.

Google-таблиці **свідомо спільні** з оригіналом: Slavik і datasheet-довідник ведуться руками,
і дублювати їх означало б вводити ціни двічі та отримати розходження. Вони належать акаунту
`anna.escore@gmail.com` — це одне джерело правди для обох сайтів, а не залежність від чужого репозиторію.

Якщо копія має читати інші таблиці, ніж оригінал, — код правити не треба:
достатньо задати змінні в **Settings → Secrets and variables → Actions → Variables**
(`SLAVIK_SHEET`, `SOLARITY_MIRROR`, `DS_SHEET` тощо). Порожня змінна = джерело вимкнене.

## Що шукаємо

| Категорія | Фільтри пошуку | Бренди |
|-----------|----------------|--------|
| **Інвертори** | потужність (кВт, від/до), фазність (1/3), напруга АКБ (HV/LV) | **Deye + Felicity** |
| **Батареї** | ємність (кВт·год, від/до), напруга (HV/LV) | **Deye + Felicity** |
| **Панелі** | потужність (Вт, від/до), **розмір** (малі / середні / великі) | будь-який бренд |

Скрізь є перемикач **«лише в наявності»**.

**Пошук за назвою.** Окреме поле зверху шукає за назвою одразу **по всіх групах** (інвертори + батареї + панелі) —
напр. «Deye 12K SG04», «Felicity IVEM6048» або «Jinko 620». Кілька слів = усі мають збігтися.
Порожнє поле повертає до пошуку за вкладками.

## Ціни

У результатах є стовпець **ЦІНА** (валюта підписана). Зверху — два перемикачі:

- **Ціна: Готівка / ПДВ** — готівкова ціна або з ПДВ. Не всі постачальники дають ціну з ПДВ:
  у кого її немає (більшість — лише готівка), у режимі «ПДВ» стоїть «—». Їхня ціна видна в «Готівка».
- **Кількість: до 36 / 36–108 / понад 108** — для панелей із тарифами за палетою (напр. RaTech):
  ціна за 1 Вт змінюється залежно від обсягу.

## Як це працює

Три частини, повністю статичний хостинг (GitHub Pages), без сервера й без бази даних:

```
джерела постачальників ──►  build.mjs  ──►  catalog.json  ──►  index.html (пошук)
     (раз на добу, GitHub Actions)              (дані)          (статична сторінка)
```

1. **`build.mjs`** — збирач. Раз на добу ходить по всіх джерелах постачальників, розбирає їхні
   назви / наявність / ціни в єдиний формат і перезаписує `catalog.json`.
2. **`catalog.json`** — готові дані каталогу (масив позицій).
3. **`index.html`** — сторінка пошуку. Завантажує `catalog.json` і фільтрує його у браузері.

Оновлення автоматичне: GitHub Action `refresh-catalog` запускається **раз на 3 години**
(а також вручну — вкладка **Actions → refresh-catalog → Run workflow**). Якщо дані змінились —
бот комітить новий `catalog.json`, і GitHub Pages за хвилину показує оновлення.

Перед комітом працює перевірка: якщо в каталозі раптом менше 50 позицій, прогін падає з помилкою
і `catalog.json` **не** перезаписується — щоб масовий збій джерел не «обнулив» сайт.

## Як працює пошук (наприклад, за потужністю)

**1. Під час збірки потужність витягується з назви в число.**
`build.mjs` розбирає назву кожної позиції та кладе потужність в окреме числове поле:

- панель `Longi Hi-MO X10 LR7-72HVD 650W` → `watt: 650`
- інвертор `Deye SUN-20K-G04` → `kw: 20`
- батарея `Felicity FLA48280 51.2V 280Ah` → `kwh: 14.34` (з напруги × ємність)

Число нормалізується **один раз при збірці**, тому по ньому можна шукати однаково по всіх постачальниках.

**2. Під час пошуку йде порівняння діапазону.**
Коли ти вводиш «від 600» і «до 650» у вкладці «Панелі», сторінка лишає позиції, у яких
`watt` потрапляє в діапазон. Порожнє поле = без обмеження. Зверху накладаються інші фільтри
(наявність, фазність, HV/LV), а результат сортується так, щоб позиції «в наявності» були вгорі.

> **Обмеження:** потужність береться з **тексту назви** за шаблоном. Якщо постачальник написав назву
> нестандартно і числа в ній немає — позиція може не потрапити під фільтр потужності (у списку лишиться).

**Розмір панелі.** Для панелей є фільтр «Розмір» і стовпець з габаритом (мм):
**малі — до 465 Вт**, **середні — 480–485 Вт**, **великі — понад 485 Вт**. Пороги — у `panelSize()` у `build.mjs`.

## Дзеркало Solarity

Таблиця Solarity належить постачальнику і приватна, тому GitHub Action не може читати її напряму.
Рішення — **публічне дзеркало** у Google Sheets на акаунті ESCORE, яке тягне дані через `IMPORTRANGE`:

- дзеркало: [1i3u_awTfs-…vg70](https://docs.google.com/spreadsheets/d/1i3u_awTfs-TMYt1YvHqXmfzguB_ThPGSt4bJYh4vg70/edit) (доступ «Всім, хто має посилання — Переглядач»)

Якщо постачальник закриє доступ — дзеркало спорожніє, але каталог не зламається (Solarity лишиться зі знімка).
⚠️ У самі клітинки дзеркала **нічого не писати** — це ламає `IMPORTRANGE` (виправляється Cmd+Z).

## Структура `catalog.json`

```json
{
  "generated": "2026-08-25",
  "note": "...",
  "items": [
    { "cat": "inv", "model": "Deye SUN-12K-SG04LP3", "sup": "YugTorg", "avail": "yes", "kw": 12, "ph": 3, "hv": false, "price": { "cash": 1600, "vat": 1730, "cur": "у.е." } },
    { "cat": "bat", "model": "Felicity FLA48280", "sup": "Slavik", "avail": "soon", "kwh": 14.34, "hv": false, "price": { "cash": 1680, "cur": "$" } },
    { "cat": "pan", "model": "Jinko 620", "sup": "Sakoenergy", "avail": "soon", "watt": 620, "ds": "https://…" }
  ]
}
```

- `cat` — `inv` | `bat` | `pan`
- `avail` — `yes` | `soon` | `no`
- `price` — `{ cash?, vat?, cashTiers?[3], vatTiers?[3], cur }` (може бути відсутня)
- `ds` — посилання на datasheet (за наявності)

## Запуск копії з нуля

1. **Залити файли** в репозиторій (гілка `main`): `index.html`, `catalog.json`, `build.mjs`,
   `README.md`, `.github/workflows/refresh.yml`.
2. **Увімкнути сайт:** Settings → Pages → *Source:* **Deploy from a branch**, гілка `main`, папка `/ (root)`.
   Через 1–2 хвилини сайт буде на https://annatsf.github.io/katalog/
3. **Дозволити боту комітити:** Settings → Actions → General → *Workflow permissions* →
   **Read and write permissions**.
4. **Додати секрети** (Settings → Secrets and variables → Actions → *Secrets*):
   `YUGTORG_EMAIL`, `YUGTORG_PASSWORD`, `ATMO_EMAIL`, `ATMO_PASSWORD`
   (за бажанням — запасний `YUGTORG_COOKIE`).
5. **Перевірити доступ до наших таблиць:** Slavik, дзеркало Solarity і datasheet-довідник мають бути
   відкриті «Всім, хто має посилання — **Переглядач**». Без цього бот отримає 401 і візьме ці позиції зі знімка.
6. **Перший прогін:** Actions → **refresh-catalog** → **Run workflow**. У логах кроку *Build catalog*
   видно, скільки позицій дало кожне джерело.

Поки секретів немає, сайт усе одно працює — показує дані зі знімка в `catalog.json`
і оновлює те, що читається без логіну (публічні Google-таблиці).

## Обслуговування

**Секрети** (Settings → Secrets and variables → Actions):
`YUGTORG_EMAIL`, `YUGTORG_PASSWORD` (автологін YugTorg), `YUGTORG_COOKIE` (запасний cookie),
`ATMO_EMAIL`, `ATMO_PASSWORD`.
Якщо в логах прогону біля постачальника `0 позицій` або «не авторизовано» — оновіть відповідний секрет.

**Ручний запуск / перевірка:** Actions → **refresh-catalog** → **Run workflow**. У логах кроку
*Build catalog* видно, скільки позицій дало кожне джерело.

### Як додати або прибрати постачальника

Список постачальників «зашитий» у **`build.mjs`** (README — лише опис, його треба тримати в синхроні вручну):

- **простий прайс** (Google-таблиця стандартної верстки: модель / ціна / наявність) — додати ID у блок
  **`SRC`** і рядок у масив **`SHEETS_LIVE`**: `{ sup: "Назва", id: SRC.назва }` (+ де колонка ціни).
  Таблиця має бути публічною.
- **прайс зі складною версткою** (секції, об'єднані клітинки, бренд в окремому стовпці — як Avtonomka / Slavik / RaTech) —
  потрібна окрема функція + підключення в `main()`. Це правка коду.
- **прибрати постачальника** — додати його ім'я в набір **`DROP`** (він зникне і з живого збору, і зі знімка),
  або видалити його рядок / функцію.
- Після змін оновити також **README** і рядок **`note`** у `build.mjs`.

`YUG_CATS` (YugTorg) і `ATMO_CATS` (Atmo) — масиви категорій для обходу. Datasheet ведуться в окремій
[таблиці-довіднику](https://docs.google.com/spreadsheets/d/1ARtSVPQ9n03UZdtlP3sy9iRUUDQ3dOLvLMQSsHT75Mc/edit).

## Файли репозиторію

- `index.html` — сторінка пошуку (весь UI в одному файлі)
- `catalog.json` — дані каталогу (оновлюються ботом)
- `build.mjs` — збирач каталогу з усіх джерел; блок **`SRC`** зверху — усі ID таблиць
- `.github/workflows/refresh.yml` — розклад автооновлення + перевірка «каталог не обнулився»

Ніяких зовнішніх бібліотек і збірки: `index.html` відкривається як є, `build.mjs` працює на чистому
Node 20 (тільки `fetch` і `fs`). Тому копію можна перенести в будь-який GitHub-акаунт — просто залити ці файли.
